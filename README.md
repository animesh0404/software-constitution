# Software Constitution

A personal constitution defining the principles and values that guide how I design and build software.

## Purpose

This repository contains the principles I choose to follow when I have meaningful freedom over what software I build and how it interacts with the people who use it.

The constitution is not intended to dictate how all software should be built. It describes the kind of software I want to create and the relationship I want that software to have with its users.

It exists as a reference for making design and engineering decisions consistently, while remaining open to criticism, testing, and revision.

## Constitution

The complete constitution is available in [`software-constitution.md`](./software-constitution.md).

It covers principles including:

- Human dignity
- Autonomy and agency
- Meaningful consent
- Transparency
- Benefit and avoidance of harm
- Proportionality
- Authority and power
- Data stewardship
- Reversibility
- Failure containment
- Human oversight
- Engineering restraint
- Revisability

## Scope

This constitution applies to projects where I have meaningful authorship or decision-making freedom over what the software is intended to do and how it should interact with its users.

It is not a claim that every software system, organisation, or employer must follow these principles.
